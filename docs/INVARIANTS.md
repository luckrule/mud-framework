# INVARIANTS

产品承诺。违反任一条，框架就失去存在的意义——这不是风格问题，是 bug。

规则：

- 编号 `INV-NNN`，从 001 起。
- 编号不复用；删除条目不保留正文。
- 每条一句话陈述 + 一句违反后果。
- 允许在源码注释里引用 `INV-NNN`，作为"为什么这条约束不可让步"的依据；编号由上面的"不复用"规则保证稳定，引用安全（见 ADR-0006）。编号不参与运行时判断——不按编号分支，不写进错误码或日志字段。条目删除时，引用方负责同步更新或删除引用。

---

**INV-001 连接层与业务进程解耦，业务进程可独立重启。**
违反后果：业务崩溃必然带走玩家连接，双进程架构和崩溃恢复承诺一并失效。

**INV-002 业务进程是存储的唯一写者，连接层进程不得直接写存储；旧写者退出未被观测时不得激活或重启新写者。**
违反后果：出现两个无协调的写者，事务边界与顺序保证都无法成立；`closed`、kill 返回或退出等待超时都不能代替退出确认。

**INV-003 同一 Connection 上的框架非终态请求不得并发处理，成功请求必须提交后才进入成功终态。**
违反后果：玩家连续指令互相踩踏，前一条成功指令的写入对后一条不可见，业务状态不可推理。

**INV-004 同一已绑定 Session 的框架非终态请求至多有一条处理线，终态屏障不得随 holder 接管或连接断开而丢失。**
违反后果：重连或连续接管绕过仍在处理的请求，同一玩家的状态更新顺序不可判定；终态不代表 JS handler 已停止，边界见 SPEC 3.2。

**INV-005 不同 Connection 之间在框架调度层面并发处理；实际并行度取决于后端声明的 concurrency 能力。**
违反后果：跨连接串行会抹掉异步模型的收益，吞吐退化为单线程；反过来，把调度并发当成存储并发会让单连接后端的数据互相覆盖。

**INV-006 若一个请求的多次写入不在同一事务内提交，失败或崩溃重放时会留下部分写入。**
违反后果：业务必须自行收拾不一致状态，而它通常不知道哪些写已生效。

**INV-007 每个请求都有超时上限，超时即到终态；请求到达任一终态后，其事务上下文均失效。**
违反后果：卡死的 Handler 阻塞后续调度，或保留的失效句柄在请求结束后继续读写，侵入后续请求的事务。

**INV-008 若 Input Queue 满时静默丢弃请求，指令消失且无日志、无错误码。**
违反后果：玩家指令凭空消失、不可诊断，这是最难排查的一类线上问题。

**INV-009 框架不假设后端具备未声明的存储能力。**
违反后果：在崩溃或并发时刻才暴露原子性缺失，届时已无法改设计。

**INV-010 Extension 依赖的存储能力不满足时拒绝注册该 Extension，不带病运行。**
违反后果：降级被静默吞掉，故障延后到最不该发生的时刻。

**INV-011 不承诺 exactly-once；恢复语义是 at-least-once，幂等由业务负责。**
违反后果：框架声称了做不到的保证，业务据此省掉幂等键，产生重复扣款类事故。

**INV-012 崩溃恢复保证连接保活与未确认输入重放。**
违反后果：业务进程崩溃即断线丢输入，恢复能力形同虚设。

**INV-013 若日志不是结构化的，或字段名随版本漂移，按字段检索与告警失效。**
违反后果：排障退化为人工读字符串，跨进程关联请求也无法自动化。

**INV-014 若旧错误码被复用表达新语义，依赖该码的下游按旧含义继续处理。**
违反后果：告警与业务分支静默错判，且没有任何信号提示语义已变。

**INV-015 若框架核心包包含具体传输实现或 import 具体传输包，更换协议必须改动核心。**
违反后果：传输不再是可替换边界，框架退化为某个传输的附属品。

**INV-016 框架包只定义存储接口与能力声明，不包含任何后端实现，也不 import 具体后端。**
违反后果：后端与框架发版互相拖累，换后端要改核心，可插拔承诺失效。

**INV-017 `concurrency: single` 的后端必须在内部串行化事务，同一时刻只有一个事务处于开启状态。**
违反后果：并发请求的语句被并入同一事务，一方回滚会抹掉另一方已提交的数据，且不抛任何错误。
