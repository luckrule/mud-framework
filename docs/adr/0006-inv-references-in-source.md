# ADR-0006: 源码注释中的 INV 引用

## 背景

`INVARIANTS.md` 原先同时有两条规则：

- 编号只增不删；删除条目时保留编号并标注"已废弃"，不复用号段。
- 不在源码里硬编码 INV 编号。改号不应引起代码改动。

第二条防的是"改号"，第一条却保证编号不会改。禁止引用与编号政策因此矛盾：编号已经稳定，引用不会因编号变动而失效，而源码注释恰恰需要引用它来说明"为什么这条约束不可让步"。实际代码已经用 `INV-002`（存储唯一写者）、`INV-004`（同一 Session 单处理线）等作为论证依据；删掉引用只能让注释改写成不变量正文的副本，或留下没有依据的断言。

## 决定

允许在源码注释里引用 `INV-NNN`，作为"为什么这条约束不可让步"的依据。编号的稳定性由 `INVARIANTS.md` 的"编号不复用；删除条目不保留正文"规则保证。

引用不得参与运行时判断：

- 不按编号分支，不把编号写进错误码、日志字段或 wire 数据。
- 编号是文档标识，不是协议的一部分；运行时契约由 SPEC 7.2 的错误码与 SPEC 7.1 的日志字段名承载。
- 条目删除时，引用方负责同步更新或删除引用。

不参与运行时的理由：一旦编号进入运行时，修改文档就会改变运行时契约，同一语义也会有两套标识。错误码已经有一套自己的稳定性规则（首个对外发布版本后只增不删、语义变更分配新码，SPEC 7.2），INV 编号不应成为第二套。

## 后果

- 注释可以直接指向产品承诺，不必复述整条不变量；搜索 `INV-NNN` 能找到该承诺在代码中的全部引用。
- 修改或删除 INV 条目时，需要检查并同步源码引用；这是允许引用后新增的维护成本，也是 `INVARIANTS.md` 已写明的责任。
- 编号不进入 wire、错误码或日志，运行时行为与 INVARIANTS 的文本编辑解耦。
- 本决定依赖"编号不复用；删除条目不保留正文"；若该规则改变，本 ADR 必须重新评估。
